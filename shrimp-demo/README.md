# 小龙虾桌宠后端 Demo

基于 Go 1.25.8 实现的桌宠后端服务，提供动作管理和状态转换功能。

### 设计模式

1. **策略模式 (Strategy Pattern)**
   - 每个动作独立实现 `Action` 接口
   - 动作之间完全解耦，易于扩展

2. **状态模式 (State Pattern)**
   - 状态机管理桌宠状态流转
   - 状态转换有明确的规则约束

3. **注册表模式 (Registry Pattern)**
   - 集中管理所有可用动作
   - 支持动态查找和匹配

## 功能特性

### 动作系统
- **搜索动作**: 小龙虾开始执行搜索任务，切换为「出发」动作
- **专注动作**: 小龙虾动作从「翻找」逐渐变为「专注阅读」
- **兴奋动作**: 小龙虾突然兴奋起来，切换为「发现宝贝」动作
- **整理动作**: 小龙虾切换为「整理资料」状态
- **交付动作**: 小龙虾切换为「郑重交付」动作
- **思考动作**: 小龙虾进入「思考模式」，动作切换为「托腮」
- **待命动作**: 小龙虾切换为「安静待命」动作

### 关键词触发
每个动作都有对应的触发关键词，系统会根据用户消息自动匹配：
- `搜索` → 搜索动作
- `专注` → 专注动作  
- `有用` → 兴奋动作
- `整理` → 整理动作
- `好了` → 交付动作
- `思考` → 思考动作

## API 接口

### 基础接口
- `GET /health` - 健康检查
- `GET /api/v1/status` - 获取当前状态
- `GET /api/v1/actions` - 获取所有可用动作

### 功能接口
- `POST /api/v1/message` - 处理用户消息，返回匹配的动作
- `POST /api/v1/search` - 触发搜索任务（模拟）
- `POST /api/v1/think` - 触发思考任务（模拟）
- `POST /api/v1/reset` - 重置状态

## 快速开始

### 1. 安装依赖
```bash
go mod tidy
```

### 2. 启动服务
```bash
go run main.go
```

### 3. 测试 API

**获取当前状态:**
```bash
curl -X GET http://localhost:8080/api/v1/status
```

**获取所有动作:**
```bash
curl -X GET http://localhost:8080/api/v1/actions
```

**处理用户消息:**
```bash
curl -X POST http://localhost:8080/api/v1/message \
  -H 'Content-Type: application/json' \
  -d '{"message":"帮我查一下明天面试这家公司的信息"}'
```

**触发搜索任务:**
```bash
curl -X POST http://localhost:8080/api/v1/search \
  -H 'Content-Type: application/json' \
  -d '{"company":"腾讯"}'
```

## 扩展指南

### 添加新动作
1. 在 `action/` 目录创建新的动作文件
2. 实现 `Action` 接口
3. 在 `registry.go` 中注册新动作

### 修改状态转换规则
在 `state/machine.go` 的 `isValidTransition` 方法中修改状态转换矩阵

### 集成 LLM 模型
1. 在 `service/shrimp.go` 的 `ProcessUserMessage` 方法中调用 LLM API
2. 根据 LLM 返回的内容决定动作和状态
3. 将动作描述传递给前端显示

## 技术栈

- **Go 1.25.8**: 主要编程语言
- **Gin**: HTTP Web 框架
- **标准库**: `net/http`, `sync`, `time`

## 设计原则

1. **简单性**: 只实现核心功能，避免过度设计
2. **解耦**: 动作、状态、服务层分离
3. **可扩展**: 易于添加新动作和状态
4. **实用性**: 直接面向用户故事实现
