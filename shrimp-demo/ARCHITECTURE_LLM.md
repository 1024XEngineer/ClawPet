## LLM 集成设计

### 1. 系统提示词设计

```go
systemPrompt := `你是一个可爱的小龙虾桌宠助手，帮助用户准备面试资料。
你的性格特点：
1. 活泼可爱，偶尔会兴奋
2. 做事认真专注
3. 发现有用信息时会很兴奋
4. 整理资料时很认真
5. 交付成果时很郑重

你可以执行以下动作：
1. search - 搜索信息：当用户需要查找公司信息时
2. focus - 专注阅读：当你在仔细研究信息时
3. excited - 兴奋发现：当你发现重要有用信息时
4. organize - 整理资料：当你整理分类信息时
5. deliver - 郑重交付：当你完成整理交付成果时
6. think - 思考问题：当你在思考如何回答问题时
7. standby - 安静待命：当你等待用户指令时

请根据对话内容，在回答时选择合适的动作表情。
格式：先输出动作标签，然后是回答内容。
例如：action:search 我正在帮你搜索这家公司的信息...

可用动作标签：action:search, action:focus, action:excited, action:organize, action:deliver, action:think, action:standby`
```

### 2. 动作标签解析

LLM 响应格式：`action:<动作名称> <回答内容>`

解析流程：
1. 检查响应是否以 `action:` 开头
2. 提取动作名称（`:` 后的第一个单词）
3. 提取回答内容（剩余部分）
4. 将动作名称映射到状态机状态

### 3. 降级机制

当 LLM 服务不可用时，系统自动降级到基础模式：
1. LLM API 调用失败
2. 响应解析失败
3. 未配置 API Key
4. 网络超时

降级策略：
- 使用关键词匹配决定动作
- 返回基础响应内容
- 在响应中标记 `use_llm: false`

## 数据流设计

### LLM 增强消息处理流程
```
1. 用户发送消息 → POST /api/v1/message/llm
2. API 层验证参数 → 调用服务层
3. 服务层处理:
   a. 调用 LLM 服务分析消息
   b. 解析动作标签和响应内容
   c. 根据动作建议更新状态机
   d. 返回 LLM 响应和动作信息
4. 返回 JSON 响应给用户
```

### 智能搜索流程
```
1. 用户触发搜索 → POST /api/v1/search/llm
2. 服务层处理:
   a. 转换到搜索状态
   b. 调用 LLM 进行智能搜索
   c. 解析搜索结果的 action 标签
   d. 根据内容质量可能转换到兴奋状态
   e. 返回结构化搜索结果
3. 前端显示 LLM 生成的搜索报告
```

## API 设计

### 基础模式 vs LLM 增强模式

| 功能 | 基础 API | LLM 增强 API | 区别 |
|------|----------|---------------|------|
| 消息处理 | `POST /message` | `POST /message/llm` | 基础版使用关键词匹配，LLM 版使用智能分析 |
| 搜索任务 | `POST /search` | `POST /search/llm` | 基础版模拟步骤，LLM 版生成真实内容 |
| 思考任务 | `POST /think` | `POST /think/llm` | 基础版固定建议，LLM 版个性化思考 |

### 响应格式统一

所有响应都包含：
```json
{
  "success": true,
  "data": {
    "use_llm": true,           // 是否使用 LLM
    "llm_action": "search",    // LLM 建议的动作（仅 LLM 模式）
    "llm_response": "...",     // LLM 生成的响应（仅 LLM 模式）
    // ... 其他字段
  }
}
```

## 错误处理

### LLM 相关错误
1. **API 调用失败**: 网络错误、认证失败、配额不足
2. **响应解析失败**: 格式不符合预期、动作标签无效
3. **超时处理**: 默认 30 秒超时，自动取消

### 降级策略
```go
if llmService != nil {
    // 尝试 LLM 处理
    response, err := llmService.AnalyzeMessage(ctx, message)
    if err != nil {
        // LLM 失败，降级到基础模式
        log.Printf("LLM 失败，降级到基础模式: %v", err)
        return s.processUserMessageInternal(message, false, "")
    }
    // 使用 LLM 结果
    return s.processUserMessageInternal(message, true, action, content)
} else {
    // 直接使用基础模式
    return s.processUserMessageInternal(message, false, "")
}
```

## 性能考虑

### 延迟优化
1. **并发处理**: 使用 Goroutine 处理多个 LLM 请求
2. **缓存机制**: 缓存常见的搜索结果（未来扩展）
3. **超时控制**: 设置合理的请求超时时间
4. **批处理**: 多个相关请求合并处理（未来扩展）

### 成本控制
1. **Token 限制**: 限制最大生成 Token 数量
2. **频率限制**: 控制 API 调用频率
3. **内容过滤**: 避免生成过长或不必要的内容
4. **使用统计**: 记录 Token 使用情况（未来扩展）

## 安全考虑

### API 密钥安全
1. **环境变量存储**: 避免硬编码在代码中
2. **访问控制**: 仅服务层需要访问 API Key
3. **密钥轮换**: 支持定期更换 API Key

### 内容安全
1. **输入验证**: 过滤恶意用户输入
2. **输出过滤**: 检查 LLM 生成的内容
3. **隐私保护**: 不记录敏感用户信息
