# ClawPet 项目架构文档

## 项目概述

ClawPet 是一个基于Go语言的虚拟桌宠后端服务，采用微服务架构设计，提供动作注册、智能对话和状态管理功能。项目遵循简洁、模块化的设计原则，易于扩展和维护。

## 技术栈

### 核心框架
- **Go 1.25.8**: 主要编程语言
- **Gin**: 高性能HTTP Web框架
- **Zap**: Uber开源的快速、结构化日志库

### 外部服务
- **DeepSeek API**: 大语言模型服务，提供智能对话能力

### 开发工具
- **Git**: 版本控制
- **Go Modules**: 依赖管理

## 架构设计

### 分层架构

```
┌─────────────────────────────────────────┐
│            HTTP API Layer               │
│          (handlers/*.go)                │
└─────────────────────────────────────────┘
                   │
┌─────────────────────────────────────────┐
│          Business Logic Layer           │
│          (services/*.go)                │
└─────────────────────────────────────────┘
                   │
┌─────────────────────────────────────────┐
│           Data Access Layer             │
│          (storage/*.go)                 │
└─────────────────────────────────────────┘
                   │
┌─────────────────────────────────────────┐
│           Data Model Layer              │
│           (models/*.go)                 │
└─────────────────────────────────────────┘
```

### 核心模块说明

#### 1. 配置管理 (config/)
- **config.go**: 定义应用配置结构
- 支持环境变量覆盖默认配置
- 集中管理所有配置项

#### 2. 请求处理器 (handlers/)
- **action.go**: 处理动作注册和查询请求
- **chat.go**: 处理聊天和上下文管理请求
- 负责HTTP请求验证、参数解析和响应格式化
- 调用业务逻辑服务处理请求

#### 3. 数据模型 (models/)
- **action.go**: 动作相关数据结构
- **state.go**: 状态管理数据结构
- **context.go**: 上下文管理数据结构
- **chat.go**: 聊天相关数据结构
- 定义所有API接口的数据结构
- 包含数据验证标签

#### 4. 业务逻辑服务 (services/)
- **deepseek.go**: DeepSeek API集成服务
  - 结构化响应解析
  - 状态变化提取
  - 错误处理和重试
- **state_manager.go**: 状态管理服务
  - 状态更新逻辑
  - 状态值范围控制
  - 状态变化应用

#### 5. 数据存储 (storage/)
- **memory_store.go**: 内存存储实现
  - 线程安全的数据访问
  - 简单的ID生成机制
  - 当前版本为内存存储，易于扩展为持久化存储

#### 6. 工具类 (utils/)
- **logger.go**: 日志工具
  - 结构化日志输出
  - 日志级别控制
  - 易于集成到各个模块

## 核心流程

### 1. 动作注册流程
```
客户端请求 → 动作处理器 → 验证请求 → 存储动作 → 生成ID → 返回响应
```

### 2. 聊天流程
```
客户端请求 → 聊天处理器 → 更新本地状态 → 调用大模型 → 解析响应 → 
提取状态变化 → 应用状态变化 → 存储上下文 → 返回响应
```

### 3. 状态更新流程
```
用户消息 → 本地规则更新 → 大模型建议 → 状态变化提取 → 
状态变化应用 → 状态值限制 → 返回更新后状态
```

## 数据结构设计

### 动作模型 (Action)
```go
type Action struct {
    ID          string `json:"id"`           // 唯一标识符
    Name        string `json:"name"`         // 动作名称
    Description string `json:"description"`  // 动作描述
}
```

### 状态模型 (PetState)
```go
type PetState struct {
    Intimacy   int `json:"intimacy"`    // 亲密度 0-100
    Frustration int `json:"frustration"` // 沮丧程度 0-100
    Happiness   int `json:"happiness"`   // 开心程度 0-100
}
```

### 状态变化模型 (StateChange)
```go
type StateChange struct {
    IntimacyDelta   int `json:"intimacy_delta"`    // 亲密度变化值
    FrustrationDelta int `json:"frustration_delta"` // 沮丧程度变化值
    HappinessDelta   int `json:"happiness_delta"`   // 开心程度变化值
}
```

### 聊天上下文模型 (ChatContext)
```go
type ChatContext struct {
    Messages []Message `json:"messages"`  // 消息历史
}

type Message struct {
    Role    string `json:"role"`     // 角色: "user" 或 "assistant"
    Content string `json:"content"`  // 消息内容
}
```

## 接口设计

### RESTful API设计原则
1. **资源导向**: 使用名词表示资源，动词表示操作
2. **HTTP方法**: GET(查询)、POST(创建)、PUT(更新)、DELETE(删除)
3. **状态码**: 使用标准HTTP状态码表示操作结果
4. **版本管理**: 当前为v1版本，API路径包含版本信息

### API端点设计
```
/api/actions/register     # 动作注册 (POST)
/api/actions             # 动作查询 (GET)
/api/chat               # 聊天交互 (POST)
/api/chat/context       # 上下文查询 (GET)
/api/chat/context       # 上下文清空 (DELETE)
/health                 # 健康检查 (GET)
```

## 状态管理设计

### 状态更新策略
1. **本地规则更新**: 基于关键词匹配的基础更新
2. **大模型智能更新**: 基于情感分析的智能更新
3. **双重更新机制**: 本地规则 + 大模型建议

### 状态值范围控制
- 所有状态值限制在0-100范围内
- 状态变化值限制在-10到+10之间
- 自动归一化处理

## 错误处理设计

### 错误分类
1. **客户端错误** (4xx): 请求格式错误、参数缺失等
2. **服务端错误** (5xx): 内部逻辑错误、外部API调用失败等

### 错误响应格式
```json
{
  "error": "错误描述信息"
}
```

### 错误日志记录
- 结构化日志记录错误详情
- 包含请求上下文信息
- 便于问题追踪和调试

## 并发安全设计

### 线程安全机制
1. **内存存储**: 使用sync.RWMutex保证并发安全
2. **上下文管理**: 使用读写锁保护共享数据
3. **状态管理**: 状态更新操作是原子的

### 资源竞争处理
- 读写分离: 读操作使用读锁，写操作使用写锁
- 锁粒度控制: 细粒度锁减少竞争
- 超时控制: 外部API调用设置超时
